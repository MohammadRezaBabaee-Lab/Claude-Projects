Default state

TRADING_MODE=paper   TRADING_ENABLED=false   LIVE_TRADING_CONFIRMED=false
Out of the box the agent watches markets, decides, records and alerts — and submits nothing. Leaving a live confirmation set while in paper mode is a startup error, so no single variable can ever flip it into live trading.

Why another trading bot?

Most open-source trading bots optimise for how quickly you can place a trade. This one optimises for everything that happens when something goes wrong.

🛑

Risk can veto the strategy

A separate risk manager runs 23 independent checks after every signal. Any failure blocks the order, and the strategy has no way to override it. Vetoes are stored with the numbers that caused them.

🔁

No duplicate trades, ever

An idempotency key is written to the database before the broker is called. A lost response triggers a lookup, never a resend. Crashes, timeouts and retries are covered by dedicated failure tests.

🔍

Every decision is explainable

Buys, sells, holds and vetoes all store the signal, indicator values, portfolio state, each risk check and the sizing arithmetic — in plain language you can read months later.

🧪

Backtests that don't flatter you

Signals compute at the close and fill at the next open, so look-ahead is impossible by construction. A test tampers with future prices and asserts nothing before the cutoff changes.

⚡

Failure is a first-class case

Broker outages, stale quotes, malformed prices, partial fills, unknown submission outcomes and mid-flight restarts each have a defined behaviour and a test that proves it.

🔌

Not tied to one broker

Strategies never import the broker layer — a test enforces it. Adapters ship for a simulated broker and for Alpaca; Saxo and Nordnet are documented as the next Nordic additions.

How it works

Market data enters at the top and an order leaves at the bottom. Every stage can stop the flow, and nothing skips a stage.

Three stages, in order

Each stage must be passed before the next is used. The first two carry no financial risk at all.

1

Backtesting no risk

Replays history through the complete strategy, risk and portfolio engine. Reports CAGR, Sharpe, Sortino, maximum drawdown, win rate, profit factor, transaction costs, slippage, exposure and position concentration — with look-ahead and survivorship controls built into the engine.

2

Paper trading no risk

The live agent loop against real or delayed market data, with orders routed to a simulated broker that models cash, commissions, slippage, market hours, partial fills, rejections and order-status transitions. State survives restarts.

3

Live trading gated, off by default

A real brokerage adapter that only points at the live endpoint once five configuration values and one command-line flag all agree. Every risk limit, the kill switch and the circuit breaker apply unchanged.

Quick start

No broker account and no network access needed for the first two commands — synthetic prices are generated locally and deterministically.

Install

# clone and install
git clone https://github.com/MohammadRezaBabaee-Lab/Claude-Projects.git
cd Claude-Projects/trading-agent
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
trading-agent validate-config

Backtest, then paper trade

# Stage 1 — a full backtest on synthetic prices
trading-agent backtest --synthetic \
    --symbols AAA,BBB,CCC \
    --start 2022-01-03 --end 2024-12-31

# Stage 2 — one paper-trading cycle
MARKET_DATA_PROVIDER=synthetic TRADING_ENABLED=true \
    trading-agent run --once

The live-trading gate

Real orders are submitted only when every row below holds. Each is checked when the process starts, and again inside the order manager at the moment of submission.

ConditionEnforced where
TRADING_MODE=liveConfiguration validator
TRADING_ENABLED=trueConfiguration validator, risk manager, order manager
LIVE_TRADING_CONFIRMED=trueConfiguration validator
LIVE_TRADING_CONFIRMATION_PHRASE equals an exact sentenceConfiguration validator
BROKER is a real adapter, never simulatedConfiguration validator
--i-understand-live-trading on the command lineCommand-line interface

Plus three properties that make the gate hard to open by accident: a live confirmation left set in paper mode is a startup error; the adapter refuses to submit a live order to any non-official endpoint; and nothing is relaxed in live mode.

Notable properties

  • Decimal money. No binary floating point anywhere a price, quantity or cash amount is computed.
  • Fail-closed config. Invalid settings stop the process rather than starting a trading system in a nonsensical state.
  • Real trading calendars. Holidays and early closes via exchange_calendars; XNYS and XSTO supported.
  • Full audit trail. Fourteen tables covering decisions, orders, fills, snapshots, risk events and configuration changes.
  • Structured logs. JSON with a correlation id per cycle, and a redaction filter so credentials never reach a log line.
  • Prometheus metrics. Latency, rejection rate, data age, exposure, drawdown and P&L.
